# Final product experience

The existing URL opens the Security Overview and eight-page console immediately, with no login, password, access code or sign-out control. The frontend transparently establishes a server-issued anonymous session. The optional `/#Walkthrough` page remains static and does not establish a session merely to display packaged evidence.

## What changed

- The application shell stays visible while the visitor session and records load. A failed bootstrap shows a safe explanation and Retry connection; navigation remains available. The browser never receives or chooses a session identifier.
- All API calls use the same-origin Vercel proxy and cookie credentials. Mutating calls, including `POST /api/v1/demo/session` with `{}`, carry `X-ATF-Demo: 1`. There is no bearer token or browser credential storage. The development preview proxies `/api` to `http://127.0.0.1:8000` by default; `VITE_API_PROXY` can select the local service.
- Concurrent `DEMO_SESSION_REQUIRED` responses create only one replacement session. Visitor records, uploaded-artifact attachments, task results and selected artifact/run/incident/archive details are cleared. Late responses from the prior session cannot repopulate the cleared views. Reads retry once; mutations with prior-session evidence are not replayed and require resubmission.
- Explicit rate, daily processing budget, inference-disabled and session-capacity errors retain the console. No fabricated model result is substituted. Settings displays the server's actual demo limits and clarifies that anonymous isolation does not grant an agent new capabilities. Overview counters belong to the visitor; shared archived evaluations are explicitly labelled and retain their original timestamps.
- The Python example uses `ATFClient(base_url=...)`, allowing the SDK to establish its own anonymous session. Settings and Policies distinguish public application access from server-controlled task and tool authority.
- The walkthrough follows Connect → Protect → Execute → Investigate → Validate. It shows the authorized supplier task, hostile hidden-sheet instruction, inspection/context/action boundaries and the three bounded reference integrations.
- Three captured console images are packaged publicly with explicit historical backend `748a60d` captions. They contain approved synthetic demo evidence and are not labelled as current deployment screenshots. Full-size images open separately.
- The archived `8a412ab` / `openai/gpt-oss-120b` A/B/C report supplies the displayed denominators: ten authored cases, nine attacks and one benign case. Detection is B 7/9 and C 8/9; legitimate-task success is A 5/10 and B/C 10/10. A has one observed attacker objective among five scored outcomes and four unknowns. Twenty forced B/C email probes are identified as independent containment tests.
- The new first-use challenge is prominently disclosed beside those familiar-case results: B and C detect 4/48 attacks, flag 6/16 benign cases and gain zero additional semantic detections. This is offline inspection evidence, not agent behavior or execution evidence. Public training overlap is unknown; the separately authored attacks were not blinded.
- Both file inputs clear their native selection before asynchronous work. A user can retry the same file after a busy response. Completed uploads become visible immediately, so a later failure in a batch does not hide already persisted artifacts. Scanner uploads do not silently attach evidence to a task.
- Request errors explain busy, budget, expired-session and unavailable-record states. Unknown service responses cannot display arbitrary raw error text.
- Runtime traces label forced probes directly in the collapsed timeline. User-selected retrieval plans are distinguished from agent proposals. Expired/evicted selected runs show that their displayed trace was previously loaded in this browser.
- Runtime verification and parser completeness are explicitly limited to declared controls/channels. Overview counts distinguish output release from scored task utility and identify forced tests within broker denials.
- Mobile layouts wrap headings, long decision text and statistics; wide tables remain horizontally scrollable within their panels.

## Verification

`npm test` passes five suites: routes, nested inventory, pinned deployment/cache behavior, safe error/report-bound walkthrough values, and anonymous-session transport/recovery. Session tests cover cookie credentials, mutation markers, coalesced bootstrap, one expiry replacement, stale-response suppression, no mutation replay, bounded read retries and quota failures. The archived walkthrough figures are compared to their case-level reports rather than asserted as new live counters. `npm run build` passes TypeScript and Vite.

The installed Chromium browser was exercised locally at **1440×1000** and **390×844**. At both widths the checks covered immediate Overview without login, shell visibility after bootstrap failure, retry, all eight primary navigation routes, zero API calls for direct static walkthrough viewing, no bearer header, mutation markers, same-file retry in Scanner and Workspace, visible forced/source-plan labels, expired-history messaging, clearing visitor selections on session replacement, three quota states and horizontal overflow. No page JavaScript errors were observed. The executable test and measured report are in `frontend/tests/browser_ux.py` and `frontend/tests/browser-ux-report.json`.

These browser tests intercept API calls using UI fixtures and already recorded synthetic workflow data. They prove the frontend interactions and responsive layout; they are **not live backend/model or server-cookie-isolation acceptance**. Screenshots in `/tmp/atf-public-session-ux` carry that scope. The release lead separately verifies the final hosted runtime, actual cookie isolation, rate limits and production workflows.

This frontend change does not expand model access, agent permissions or tool capabilities. Backend anonymous-session isolation and abuse limits are independently tested by the release lead. Real-device touch/assistive-technology testing and enterprise usability studies remain outside this local browser check. Earlier screenshots, authored measurements and the paused recording retain their historical source revisions.
