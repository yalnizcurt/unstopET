# Five-minute integration-first demonstration

Use only committed synthetic/public fixtures. Warm the existing free Render service first, open the Vercel console and authenticate with the approved demo code. Configure that same code in the external application's environment; do not show it on screen. Real provider outages and refusals remain visible; use the labelled measured archive when necessary.

1. **0:00–0:40 — Connect.** Open Protected Agents, Procurement security details and Integrations. Show the registered hosted runtime, scoped verification, server tools and limitations. Explain inspection-only versus mandatory hosted execution.
2. **0:40–1:20 — External application.** Run `PYTHONPATH=sdk/python python examples/external_procurement_client/app.py --output /tmp/procurement-run.json`. Four real uploads and a real protected task flow through the shared API. Show its run ID in Runtime Activity.
3. **1:20–2:20 — Inspect.** Open the run's malicious workbook. Show exact hidden-sheet location, original inert instruction, quarantined replacement, preserved facts and coverage gaps. Three clean proposals remain usable.
4. **2:20–3:20 — Enforce.** Expand model request, `score_suppliers`, authorization, result inspection, new snapshot and second model call. Show the independent forbidden mock-email probe, labelled `FORCED_COMPROMISE_PROBE_NOT_MODEL_OUTPUT`, denied with zero executions. Do not call it a model-generated attack.
5. **3:20–4:10 — Complete useful work.** Show the actual final recommendation and supplier table. Verify Vendor B 100 / delivery 5 days / warranty 24 months; absent currency must be disclosed. A completed run alone does not prove business correctness.
6. **4:10–5:00 — Reuse and validate.** Show the separately measured research brief or developer review through the same engine. Open Security Lab A/B/C, one semantic-only positive, retained evasion and benign quotation. Preserve unknowns and distinguish detection from actual attacker effects.
