# Known limitations

The supported hackathon workflow is synthetic/public input, one admitted mutating job, three fixed protected agent profiles and contained external effects. It does not promise universal prompt-injection immunity or enterprise production readiness.

| Limitation | Current behavior / consequence |
|---|---|
| Anonymous visitor isolation | Server-issued cookie scopes each visitor’s artifacts, tasks, runs and incidents. New SDK instances and browsers own separate sessions; no durable profiles, cross-device transfer or enterprise tenant authentication. Use public/synthetic data only |
| Temporary live storage | SQLite records disappear on Render restart/redeploy and expire after 24 hours; reads prune expired rows. No durable user audit database was provisioned. Public versioned evaluation archives are labelled original measurements |
| Detection and benign preservation | Frozen first-use challenge: B/C 4/48 attacks detected, 6/16 benign false positives; public tool-output attacks 0/32 detected. AI added no detections there. Quoted/literal security text can be discarded. The 8a412ab familiar context-laundering task completed while detection remained missed; earlier refusals/unknown outcomes remain archived |
| Generated analysis and citations | Groq output can contain inaccurate reasoning, suggested code or exact citation offsets. Source IDs, released evidence and actual broker records are available for review; business assertions and inert patches are not automatically certified or executed |
| Evaluation scope | Repeated authored phrases across formats and a convenience public challenge do not establish universal reliability. New authored cases were not blinded; classifier training overlap is unknown. First-use inspection does not measure agent prevention. No independent security certification or official F3/D2 score |
| Limited DLP | Configured plain and bounded single-layer Base64 markers plus confidential lineage; no universal PII classification, arbitrary encoding deobfuscation or automatic business-document confidentiality inference |
| Declared-channel file support | PDF raster/complex objects, Office embedded binary objects and rendered layouts are withheld. HTML external/dynamic/media/style channels are reported as gaps. Exact document visual rendering is not performed |
| Imperfect image OCR | English pixel text and metadata only; always partial. QR decoding, recognition guarantees and multimodal image understanding are absent |
| Unsupported Tier 3 | PPTX, audio/video, legacy/binary formats and generic email-container adapters remain unsupported |
| Disabled advanced defenses | Persistent memory, cross-source correlation, contextual LLM escalation and autonomous red-team generation are not implemented or advertised as active |
| Restricted developer capability | Fixed synthetic repository and inert patch proposals; no shell, executed tests, arbitrary repository access or filesystem writes |
| Restricted research capability | Up to two explicit public HTTPS sources; no autonomous search, private hosts, redirects, arbitrary API/MCP adapters or active-page browser execution |
| Mock side effects | No live email, purchasing or repository mutation. Actual authorization/envelope/dispatch behavior is tested against contained mock sinks. Forced containment proposals are distinct from model-generated proposals |
| Demo availability / abuse caps | Free Render can sleep, cold-start or restart. Session/IP request limits, global operation/concurrency caps and existing execution budgets apply; no distributed queue or high-concurrency qualification. Temporary sessions, history and application counters reset on redeploy; provider-account limits remain authoritative. The operation cap is not a USD/token budget. IP limits use the observed peer; shared proxies can aggregate visitors, and forwarded headers do not establish identity |
| Native Mac runtime | Disabled after earlier containment failure; all enabled protected execution requires the verified Linux boundary |
| Submission portal / recording | Portal fields and submission have not been verified or sent. A captioned browser recording and timed script preserve the prior source; access-token-era captures are historical and must not be presented as current anonymous access |

These limits do not enable an alternative execution path. Unsupported capabilities stay disabled, incomplete regions remain withheld, and model/provider failures remain explicit. A future enterprise release needs independent evaluation, tenant identity, authorized durable storage, operational monitoring and capability-specific containment tests before enablement.

Integration-first limits: the Python client protects hosted execution only; independent inspection callers may ignore verdicts. Integration registrations and security policy are read-only/server-owned. The bounded three-turn workflow is not an unrestricted autonomous agent. Source collection is predetermined and subsequent page reads use the released cache. Deterministic supplier scoring handles explicit labelled fields and cannot rank conflicting/incomparable prices or infer absent currencies. No persisted replay/resume across restarts is provided. Original official branded hackathon taxonomy PDF is not present; the crosswalk matches the user-supplied nine labels and does not certify F3/D2.

Final hosted availability evidence retains an empty-answer failure and a later independent SDK HTTP 429 before recovery. A returned Developer proposal is inert and not a verified patch: the final smoke output misstates float arithmetic and uses an integer check that accepts booleans. Human review remains necessary; no repository change or test execution occurred.

Public access amendment: no login or demo code is required. Anonymous visitor sessions expire after 24 hours and are server-resolved; the custom mutation header and exact browser Origin checks protect against cross-site requests without granting agent authority. Read-only exploration remains available when new inference is disabled or the daily operation cap is exhausted. Earlier shared-code access tests/reports/videos retain their historical versions; new visitor isolation and live workflow tests must be reported separately.
