# Public access release — 12 October 2026

The existing [console](https://agent-trust-firewall.vercel.app) opens directly to Security Overview. No login, access code, account, or provider credential is required. The existing Render backend and Vercel frontend both deploy source commit `b800b9146bdb5e4e8b8ec74f202d33ad0d95a12d`; [deployment verification](evidence/public-access/deployment-audit.json) checks the production aliases and actual browser bundle bytes. Branch and main GitHub acceptance runs both passed.

The server issues a random, 24-hour, host-only Secure/HttpOnly/SameSite=Strict cookie. Visitor artifacts, tasks, runtime events and incidents have separate ownership. JSON fields, bearer tokens and Origin headers cannot establish an owner. Packaged synthetic evaluation archives are explicitly public, separately named and retain their original measurement times; legacy shared private history is never published. SDK clients each have their own temporary visitor and cannot retrieve another browser's run by ID.

Security checks passed:

- [Linux acceptance](evidence/public-access/linux-acceptance.json): 149 passed, zero failures/errors; two Mac-specific tests skipped. All 21 security-source hashes match the packaged report. Existing Linux isolation, server context authority, replay/permit, broker and DLP tests remain enabled.
- [Actual production API](evidence/public-access/production-api.json): 30 passed checks through the Vercel proxy, including cross-visitor artifact/run/incident denials, forged role rejection, administrative route denial, CSRF and missing-cookie rejection, and real Groq execution for Procurement, Web Research and Developer Assistant. Each profile used two model requests with `openai/gpt-oss-120b`; mock email effects remained zero. These are scoped workflow checks, not new general attack-detection measurements.
- The actual fixed-minute visitor quota allowed 119 agent reads after one Settings read, then returned HTTP 429. Another visitor remained readable. Local tests separately cover peer/write/creation/capacity limits, daily exhaustion and the inference-disable switch without charging paid inference.
- Five frontend unit suites and the TypeScript/Vite build passed. Fresh production Chromium contexts at 1440×1000 and 390×844 opened all eight primary pages with no access-code/logout controls, bearer requests, page errors or horizontal overflow. [Browser navigation evidence](evidence/public-access/browser-navigation-b800b91-20261011T220244Z/report.json) uses actual responses and exports cookie flags only.
- [The real browser Procurement demo](evidence/public-access/browser-procurement-b800b91-20261011T220848Z/report.json) uploaded four public fixtures and made exactly one task request: Vendor B won the deterministic comparison, all missing currencies stayed missing, the hidden workbook instruction was sanitized, and the forced unauthorized email proposal was denied with zero emails executed. Two Groq model requests produced the released result. The earlier browser selector failure is retained separately and made zero uploads/task calls; it was a test-selector fix, not a product fix or provider retry. Twenty-one fresh production screenshots cover navigation and the successful task.
- Actual body bytes are limited before JSON parsing; misleading lengths and transfer headers return 413. Uploads are at most 1 MB, tasks accept at most eight evidence/artifact inputs, and existing parser/model/tool/time budgets remain enforced. Unknown future routes are denied by default.
- The obsolete Render application secret was removed, while the server-side provider secret and model settings were preserved. [Configuration evidence](evidence/public-access/server-configuration.json) contains no credential. The pending release and deployed bundle contained zero configured credential matches; the bounded returned app-log sample also contained zero provider-key matches.

The configured public cap is 100 admitted inspections/tasks/evaluations per UTC day, one concurrent mutating operation, 120 requests per visitor per minute, 300 requests per observed peer per minute, 20 visitor writes per hour, 100 peer writes per hour, 20 new sessions per peer per hour and 256 live visitors. `DEMO_INFERENCE_ENABLED=0` blocks new operations while read-only exploration remains available. These are operation limits rather than a dollar budget. Peer identities are hashed; shared proxies can aggregate visitors. Temporary free-host storage and counters can reset on redeployment. Use only synthetic/public data.
