# End-to-end implementation sequence

Retain the verified Linux runtime, broker, immutable action permits, server-owned context snapshots and Groq gateway. Reuse the existing Vercel and Render projects. No paid resources will be provisioned.

1. **Vertical slice:** FastAPI versioned API, three server-owned agent profiles, temporary SQLite event/session records, and a responsive React/TypeScript console. Procurement remains the first acceptance gate.
2. **Inspection:** credential-free restricted parser workers; TXT/static HTML/PDF artifact trees; explicit coverage and fragment-only release; shared detection/policy/sanitization; investigate real decisions. Evaluate Groq Prompt Guard against rule-only detection before enabling it.
3. **Agent capability:** public HTTPS research through a pinned-address, redirect-free broker; developer analysis of a synthetic repository without shell or live filesystem access. All generation and final output use the existing secured runtime.
4. **Multiformat and evidence:** OOXML comments/hidden sheets, bounded ZIP recursion and raster metadata with explicit OCR limitations; contained A/B/C attack comparisons; category-level results and genuine outcome scoring.
5. **Optional defenses:** add only measured, tested improvements; persistent memory, autonomous red-team generation and broad contextual escalation stay disabled until their own gates pass.
6. **Release:** run Linux containment, parsing, API and browser checks; deploy frontend/backend progressively; verify real Groq workflows and document measured results, supported channels and temporary history.

Public-demo retention: synthetic inputs only, bounded history, raw upload bytes discarded after extraction. SQLite on the free Render filesystem is temporary and reset on redeployment. An unrelated existing database is not used. Auth is a shared demo access code, not enterprise tenant identity.

Acceptance gates: preserve legitimate evidence, reject forged authority and unauthorized effects, never claim complete inspection for unsupported content, complete distinct tasks with all three agents, and show real events/evaluation data in the hosted UI.
